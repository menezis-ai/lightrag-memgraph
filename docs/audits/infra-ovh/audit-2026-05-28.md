## Section 1 — Configuration Caddy

`maquette-deploy/Caddyfile` est minuscule (46 lignes). Il déclare un site unique paramétré par la variable `SITE_ADDR`.

### 1.1 — Site et binding

```
{$SITE_ADDR::80} {
    root * /srv
    encode zstd gzip
    ...
}
```

| Élément | Constatation | Cite |
|---|---|---|
| Adresse d'écoute | `${SITE_ADDR:-:80}` — par défaut HTTP plain port 80. En production, `stack.yml:34` force explicitement `SITE_ADDR: ":80"`. | `Caddyfile:10`, `stack.yml:34` |
| TLS / ACME natif Caddy | **Désactivé.** Caddy écoute en HTTP plain. La terminaison TLS est déléguée à Traefik en frontal (voir §1.2). | `Caddyfile:10`, `stack.yml:34` |
| Reverse proxy `/api/*` | `handle_path /api/*` → upstream `${BACKEND_ADDR:-twin-maquette_api:8000}`. `handle_path` strip le préfixe `/api`. | `Caddyfile:20-25` |
| Headers upstream | `X-Forwarded-For {remote_host}` et `Host {host}` injectés vers le backend. | `Caddyfile:22-23` |
| Compression | `zstd` puis `gzip` (negotiation) sur la totalité des réponses servies par `file_server`. | `Caddyfile:12` |
| MIME fixé `*.jsx` | `Content-Type: application/javascript; charset=utf-8` pour les *.jsx (le SPA est du JSX inline lu par Babel CDN). | `Caddyfile:36-37` |
| Redirect racine | `/` → `/Twin%20RAG%20WebUI.html` (302). | `Caddyfile:30-31` |
| `file_server` | Sert le contenu de `/srv` directement (copie de `source/` dans le Dockerfile). | `Caddyfile:39`, `Dockerfile:12` |

### 1.2 — Architecture TLS réelle (Traefik en frontal)

Le `stack.yml:40-50` montre que la terminaison TLS est faite par **Traefik** (déjà déployé sur l'hôte OVH par Dokploy), pas par Caddy :

```yaml
- "traefik.enable=true"
- "traefik.http.routers.twin-maquette.rule=Host(`maquette.sigilum.fr`)"
- "traefik.http.routers.twin-maquette.entrypoints=websecure"
- "traefik.http.routers.twin-maquette.tls=true"
- "traefik.http.routers.twin-maquette.tls.certresolver=letsencrypt"
- "traefik.http.services.twin-maquette.loadbalancer.server.port=80"
- "traefik.http.routers.twin-maquette-http.rule=Host(`maquette.sigilum.fr`)"
- "traefik.http.routers.twin-maquette-http.entrypoints=web"
- "traefik.http.routers.twin-maquette-http.middlewares=twin-maquette-https"
- "traefik.http.middlewares.twin-maquette-https.redirectscheme.scheme=https"
```

Conséquences :

| Aspect | État |
|---|---|
| Edge TLS | Traefik (resolver Let's Encrypt `letsencrypt`) |
| Forward HTTP → HTTPS | Activé via middleware Traefik `twin-maquette-https` (`redirectscheme.scheme=https`) |
| Backend Caddy ↔ Traefik | HTTP plain sur réseau Docker overlay `dokploy-network` (pas de chiffrement intra-cluster) |
| `Caddyfile:5-8` mention `SITE_ADDR="twin.erwin-labs"` | **Code mort** : le commentaire évoque un fallback où Caddy ferait son propre ACME, mais en prod c'est Traefik qui le fait. À documenter ou retirer. |

### 1.3 — Security headers Caddy

```
header {
    X-Content-Type-Options "nosniff"
    Referrer-Policy "strict-origin-when-cross-origin"
    -Server
}
```

`Caddyfile:41-45`

| Header | État | Recommandation |
|---|---|---|
| `X-Content-Type-Options: nosniff` | Présent | OK |
| `Referrer-Policy: strict-origin-when-cross-origin` | Présent | OK |
| `Server` | Stripé (`-Server`) | OK |
| `Strict-Transport-Security` (HSTS) | **Absent** au niveau Caddy. Doit être ajouté soit ici, soit côté Traefik. `[OBSERVATION LIVE REQUISE]` pour vérifier si Traefik en ajoute un. |
| `Content-Security-Policy` | **Absent.** Critique car la maquette charge React + Babel via CDN (`unpkg`, `cdnjs`). Un CSP `default-src 'self' 'unsafe-inline' 'unsafe-eval' https://unpkg.com https://cdnjs.cloudflare.com` est minimum requis. |
| `X-Frame-Options` / `frame-ancestors` | **Absent.** Risque clickjacking : `https://maquette.sigilum.fr/` peut être embeddé dans une iframe arbitraire. |
| `Permissions-Policy` | **Absent.** Pas de désactivation des features browser (camera, mic, geolocation, etc.). |
| `Cross-Origin-Opener-Policy` / `Cross-Origin-Embedder-Policy` | **Absent.** Acceptable pour une maquette statique. |
| `Cache-Control` / `ETag` | Pas explicitement configuré. Caddy `file_server` ajoute par défaut un `ETag` et `Last-Modified` (réponses 200), mais aucun `Cache-Control` ne fixe la durée. `[OBSERVATION LIVE REQUISE]` pour confirmer. |

### 1.4 — Rate limiting

**Absent côté Caddy.** Le `Caddyfile` ne déclare ni `rate_limit` (module Caddy v2 tiers), ni gestion de seuil par IP. `[OBSERVATION LIVE REQUISE]` pour confirmer s'il y a un middleware Traefik global.

Risque : tout endpoint backend (`POST /api/state/reset`, `DELETE /api/{kind}/{id}`) peut être martelé en boucle depuis une IP unique sans limite.

### 1.5 — Logging Caddy

**Aucune directive `log` dans le `Caddyfile`.** Caddy v2 a un comportement par défaut où les access logs sont écrits sur stderr du process (donc capturés par le runtime Docker `docker logs <container>`). Mais :

| Aspect | État |
|---|---|
| Format de log | Par défaut JSON sur stderr (Caddy v2). Non vérifié `[OBSERVATION LIVE REQUISE]`. |
| Persistance | Volume Docker non monté pour les logs Caddy (cf `stack.yml:56-58` : seul `twin-maquette-data` existe, mounté côté `api`). Logs vivent dans `journald` / `docker logs` jusqu'à rotation OS. |
| Rotation | Dépend de la config `daemon.json` de Docker côté hôte OVH — pas dans le repo. |
| Archivage / shipping | Aucun. Pas de Fluent Bit, Vector, Promtail, Filebeat dans `stack.yml`. |
| Centralisation | Aucune. |
| Données sensibles loggées | Caddy par défaut log les URLs (chemin, query). Les requêtes `GET /api/docs/{id}` peuvent leak des IDs dans les access logs OS, mais les payloads `PATCH` ne le sont pas (body filtré). |

### 1.6 — Mismatch documenté Caddyfile vs réalité

Le commentaire `Caddyfile:3-8` documente deux modes :

```
# Two modes selected by the SITE_ADDR env var at `docker run`:
#  - SITE_ADDR=":80"               → plain HTTP (raw IP demo)
#  - SITE_ADDR="twin.erwin-labs"   → Caddy fetches Let's Encrypt cert
#                                    automatically
```

Or `stack.yml:34` impose `SITE_ADDR: ":80"`. Le mode "Caddy ACME" n'est jamais utilisé en prod. À nettoyer pour réduire la confusion (un opérateur croyant que Caddy gère le cert pourrait être surpris quand le cert Let's Encrypt expire — c'est Traefik qui le renouvelle).

### 3.2 — Surface d'attaque sans auth

| Action publique non authentifiée | Impact | Cite |
|---|---|---|
| `POST /api/state/reset` | Reset complet de la base SQLite (DROP entities + mutations puis reseed depuis `seed-data/*.json`). Wipe de tout l'état persisté par les opérateurs (approvals, retags, tag-requests acceptés). | `main.py:228-237` |
| `PATCH /api/{kind}/{entity_id}` | Deep-merge arbitraire sur n'importe quelle entité. Un attaquant peut modifier `review.state`, `summary`, `tags` sur n'importe quel doc. Persisté SQLite. | `main.py:266-283` |
| `DELETE /api/{kind}/{entity_id}` | Suppression de n'importe quelle entité (doc, tag, etc.). | `main.py:286-297` |
| `GET /api/mutations` | Lecture du log d'audit complet, incluant les payloads PATCH (peut contenir des contenus de retag, justifications de review). | `main.py:108-131` |
| `GET /api/{kind}` | Liste complète de toute entité — par défaut renvoie tout (pas de pagination défaut). Avec ~22 tags + 14 docs + 18 events + 9 notifs, la réponse fait ~50 KB. Pas de risque DoS direct, mais data-mining facilité. | `main.py:240-246` |

### 3.3 — CORS

```python
app.add_middleware(
    CORSMiddleware,
    allow_origins=["*"],
    allow_credentials=False,
    allow_methods=["*"],
    allow_headers=["*"],
)
```

`main.py:56-62`

| Élément | État | Risque |
|---|---|---|
| `allow_origins=["*"]` | wildcard | Toute origine peut requêter le backend en JS. |
| `allow_credentials=False` | OK | Pas de session cookie, donc pas de risque CSRF auth. |
| `allow_methods=["*"]` | wildcard | OPTIONS, GET, POST, PATCH, DELETE, etc. tous autorisés. |
| `allow_headers=["*"]` | wildcard | N'importe quel header custom autorisé. |

Comme `allow_credentials=False`, le wildcard `*` n'expose pas de session XHR cross-origin (le browser n'enverra pas de cookie). Mais combiné à l'absence d'auth, ça veut dire que **n'importe quel site malveillant peut, depuis le browser d'un visiteur, déclencher `POST /api/state/reset` sur la maquette** sans CSRF token (pas de credentials à voler — le backend est simplement ouvert).

### 3.4 — Rate limit applicatif

**Absent.** Pas de middleware `slowapi`, `fastapi-limiter`, ou `aiocache` dans `pyproject.toml` ni dans le code. La maquette accepte des requêtes infinies sans throttle.

### 3.5 — Limites de payload

**Aucune limite explicite.** FastAPI/Starlette par défaut n'imposent pas de borne `max_request_body_size` sans middleware ad-hoc. Uvicorn a un défaut `--limit-max-requests` (illimité par défaut) et `--limit-concurrency` (illimité).

Le `PatchBody` Pydantic (`main.py:262-263`) accepte un `dict[str, Any]` sans borne :

```python
class PatchBody(BaseModel):
    patch: dict[str, Any]
```

Un attaquant peut PATCH un blob JSON arbitrairement gros qui sera stocké comme texte JSON dans la colonne SQLite `entities.data`. Pas de borne côté SQLite (TEXT illimité).

### 3.6 — Documentation FastAPI désactivée

Bonne décision :

```python
app = FastAPI(
    ...
    docs_url=None,
    redoc_url=None,
    openapi_url=None,
)
```

`main.py:48-55`

Conséquence : pas de `/api/docs` Swagger UI exposé (collision intentionnelle avec le kind d'entité `docs`). OK.

### 3.7 — Health endpoint expose des compteurs

`GET /api/health` renvoie `{ok, counts, mutations}` (counts par kind, total mutations). Pas un secret en soi mais permet à un attaquant de **monitorer en silence** combien d'entrées la maquette a en base sans rien casser. Faible exposition.

### 8.3 — Conflit de routage Caddy ↔ Traefik

Le `stack.yml` montre une architecture **double-layer** :

1. Traefik écoute sur `:80` / `:443` (l'entrée publique sur la VM).
2. Traefik route `Host(maquette.sigilum.fr)` vers le service Docker `twin-maquette_web` port 80.
3. Le conteneur `twin-maquette_web` exécute Caddy, qui écoute sur `:80` (selon `SITE_ADDR=":80"`).
4. Caddy sert les fichiers statiques + reverse_proxy `/api/*` vers le service `twin-maquette_api:8000`.

Conséquences :

| Aspect | Constatation |
|---|---|
| TLS terminé deux fois ? | Non : Traefik fait TLS, Caddy reçoit du HTTP plain depuis Traefik (en réseau overlay Docker). |
| Caddy fait du HTTPS lui-même ? | Non en pratique (`SITE_ADDR=":80"`), mais le `Caddyfile` mentionne ce mode (`Caddyfile:5-8`) — confusion documentaire. |
| Conflit de cert ACME ? | Risque théorique : si Caddy était activé en mode ACME (`SITE_ADDR=twin.erwin-labs`), il tenterait de bind 80/443 → collision avec Traefik. Mais en pratique, le stack n'expose pas les ports 80/443 du container Caddy directement à l'hôte (cf `stack.yml:29-39` : pas de `ports:` mapping). Caddy ne voit que `dokploy-network`. OK. |
| Headers propagés | `X-Forwarded-For` est ajouté par Caddy vers le backend (`Caddyfile:23`). Mais l'IP source que Caddy voit est l'IP Traefik (interne au cluster), donc `X-Forwarded-For` ne contient pas la vraie IP client. Pour avoir la vraie IP : Traefik doit ajouter le sien (`X-Forwarded-For: <client>, <traefik-internal>`) ET Caddy doit le passer. À vérifier `[OBSERVATION LIVE REQUISE]`. |
| Double-routage | Traefik et Caddy font tous deux du routing path-based. Pour la maquette c'est OK (Caddy gère `/api/*` et le reste, Traefik ne fait que `Host(...)` matching). |

### 8.4 — Recommandation Dokploy / Traefik

Indépendamment de la maquette :

1. Vérifier que le Dokploy UI **n'est pas exposé publiquement** sans auth (vault, MFA).
2. Vérifier que le Traefik dashboard est désactivé en publique.
3. Vérifier que le Docker socket n'est pas exposé sur TCP.
4. Vérifier que SSH est restreint (clé seule, port custom, fail2ban).

Ces points dépassent le scope du repo et nécessitent un accès hôte. À programmer.

### 10.1 — Détail R01 : `POST /api/state/reset` publiquement accessible

**Reproductibilité** : trivial. La route `POST /api/state/reset` est documentée publiquement dans le code source servi par Caddy (`backend/twin_demo_api/main.py:228-237`), accessible aussi via l'UI maquette (icône poubelle topbar, audit maquette §1.1 #14).

**Impact** :

- Wipe complet `entities` + `mutations` SQLite.
- Reseed automatique depuis `seed-data/*.json`.
- Toutes les mutations opérateurs (approvals, retags, tag-requests acceptés, edits) sont **perdues**.

**Recovery** : aucun, sauf si un backup hors-host existe (pas le cas, cf §7).

**Mitigation court terme (< 1h)** :

```python
# main.py — autour de /state/reset
from fastapi import Depends, Header, HTTPException
import os, secrets

def require_reset_token(x_reset_token: str | None = Header(None)) -> None:
    expected = os.environ.get("TWIN_DEMO_RESET_TOKEN")
    if not expected or not x_reset_token or not secrets.compare_digest(x_reset_token, expected):
        raise HTTPException(403, "Reset token required")

@app.post("/state/reset", dependencies=[Depends(require_reset_token)])
async def reset_state() -> dict: ...
```

Et côté `stack.yml` :

```yaml
api:
  environment:
    TWIN_DEMO_DB_PATH: /data/twin-demo.sqlite
    TWIN_DEMO_RESET_TOKEN: ${TWIN_DEMO_RESET_TOKEN:?required}
```

Le token est injecté via la variable d'env CI/CD ou manuellement (`export TWIN_DEMO_RESET_TOKEN=$(openssl rand -hex 32) && docker stack deploy ...`).

**Mitigation alternative côté Caddy (< 30min)** :

```
@write_unsafe {
    method POST PATCH DELETE
    path /api/*
}
handle @write_unsafe {
    basicauth {
        twin-demo $2a$14$... # bcrypt hash, never plain
    }
    reverse_proxy {$BACKEND_ADDR:twin-maquette_api:8000} {
        header_up Host {host}
        header_up X-Forwarded-For {remote_host}
    }
}
```

→ Toute méthode write nécessite un Basic Auth. Les `GET` (lecture maquette) restent ouverts.
