# Activity Audit Baseline - 2026-06-29

## Scope

This audit maps the Activity ledger events that are emitted today before adding
more business events. It is intentionally literal: when a requested event is not
emitted by a live route, the status is `missing`. Seed fixtures and UI-only
toasts do not count as backend audit coverage.

Activity query support applies across the ledger:

- `GET /activity?range=24h|7d|30d|all` filters by event `ts`.
- `GET /activity?resource.id=...` matches only `target.id`, `meta.doc_id`, or
  entries inside `meta.doc_ids`.
- `total` is the backend count after filters and before `limit`.
- `nowMs` is returned for deterministic relative-time rendering.

## Gaps Before More Business Events

- Live `source-ready` and `source-failed` emission is absent. They exist in the
  Activity model and seed fixtures only.
- Live auth Activity emission is absent for login, logout, failed login, and
  access denied. Current tests cover auth behavior but not an audit ledger event.
- Several live events are not `resource.id` searchable because their identifiers
  live under domain-specific meta keys (`entity_id`, `rel_id`, `key_id`,
  `folder_id`) rather than `target.id`, `meta.doc_id`, or `meta.doc_ids`.
- Graph, API key, folder, and some delete flows have backend/UI behavior tests,
  but no e2e assertion that the emitted event appears in Activity.
