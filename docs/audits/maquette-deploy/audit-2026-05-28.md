**Convention de catégorisation.**

| Code | Signification |
|---|---|
| `PERSISTE` | Mutation passe par `twinDb` → `/api/{kind}/{id}` → SQLite. Survit au reload. |
| `MOCK_BACKEND` | Endpoint existe mais ne fait qu'un deep-merge générique `(kind, id, data-as-json)` ou renvoie un mock statique. Survit au reload mais aucune logique métier serveur. |
| `MOCK_FRONT` | Pas d'appel backend. `useState` local + toast. Disparait au reload. |
| `DEAD` | Élément visible (bouton, badge) sans handler câblé ou avec handler `console.warn` / no-op. |

Citations format `chemin/relatif:ligne`. Tous les chemins sont relatifs à `maquette-deploy/`.

## Section 3 — État global SPA & pattern `(kind, id, data-as-json)`

### 3.1 — Architecture en lecture

```
window.MOCK_DOCUMENTS  ←  data.js:3-185      (seed JS embarqué)
                       ↓
            App.jsx::useState(MOCK_DOCUMENTS)  app.jsx:102
                       ↓
   twinDb.boot() + getAll("docs")             app.jsx:110-122
                       ↓
            GET /api/docs                     main.py:240-246

                       ↓
```

Les `window.MOCK_*` (data.js) sont visibles dans le code SPA mais **écrasés au boot** dès que la persistence répond. Si le backend est down, le SPA fonctionne sur les MOCK (`app.jsx:118-121` console.error + setDbReady(true)). C'est intentionnel (dégradation gracieuse).

### 3.2 — Architecture en écriture (PATCH)

```
User clicks "Approve"                          documents.jsx:232 (approveDoc)
   ↓

   ↓ (optimistic)

   ↓ (fire-and-forget)

   ↓

   ↓

```

### 3.6 — Évaluation du cheat `(kind, id, data-as-json)`

Le pattern est minimaliste mais cohérent pour une démo : 5 routes génériques (`GET /{kind}`, `GET /{kind}/{id}`, `PATCH`, `DELETE`, `POST /state/reset`) + 2 routes typées (`/health`, `/mutations`, `/todo`).

**Coût caché en production** :
- Toute la logique métier (cascade, side-effects, RBAC) DOIT être réécrite ailleurs.
- Le `mutations` log ne capture pas le `before`/`after`, seulement le patch envoyé — un audit complet nécessite de relire l'état précédent.
- Les indices SQLite (`entities_kind_idx`, `mutations_ts_idx`) ne suffisent pas pour des requêtes courantes (e.g. "tous les docs en pending review du workspace cib").
