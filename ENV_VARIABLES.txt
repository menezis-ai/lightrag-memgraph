================================================================================
twindb-lightrag-memgraph 1.0.0 — Environment variables reference
================================================================================

Every variable read by the package, grouped by concern. "Required" means the
runtime will not work without it; everything else has a safe default.

The BNP container entrypoint is `python -m twindb_lightrag_memgraph.lightrag_server`
(register() then LightRAG's own server); twin_main.py is the readable reference
launcher. LightRAG-native variables (OPENAI_API_KEY, LLM_BINDING, EMBEDDING_*,
SUMMARY_LANGUAGE, ...) keep working as documented upstream; only the variables
introduced or consumed by this package are listed here.

--------------------------------------------------------------------------------
0. OVERLAY ACTIVATION (read by register() when flags are not passed in code)
--------------------------------------------------------------------------------
TWIN_REPLACE_UI              "true" → serve the embedded Twin WebUI at /webui
                             instead of the native LightRAG UI.
TWIN_MOUNT_SERVER            "true" → mount the /twin/api/* overlay (folders,
                             tags, activity, graph, query).
TWIN_SHIM_NATIVE_ROUTES      "true" → shadow native /documents, /health,
                             /auth-status... with the Twin-shaped contract.

A deployment whose boot already calls a bare register() activates the full
interface by setting these three variables — no code change.

Gunicorn / import-string launchers: workers import the app in fresh
processes where a separate boot script never ran. Point the launcher at
this package's factory instead of LightRAG's:
    gunicorn 'twindb_lightrag_memgraph.asgi:get_application()'
    uvicorn --factory twindb_lightrag_memgraph.asgi:get_application
It runs register() (env-driven flags above) in every worker before
LightRAG's server module loads. Symptom when this is missing: the native
LightRAG UI loads and redirects to /webui/#/login.

--------------------------------------------------------------------------------
1. MEMGRAPH CONNECTION (required)
--------------------------------------------------------------------------------
MEMGRAPH_URI                 Bolt URI, e.g. bolt://memgraph:7687  [REQUIRED]
MEMGRAPH_USERNAME            Username. Default: "" (no auth)
MEMGRAPH_USERNAME_FILE       File containing the username. Mutually exclusive
                             with MEMGRAPH_USERNAME (Docker secrets compatible).
MEMGRAPH_PASSWORD            Password. Default: ""
MEMGRAPH_PASSWORD_FILE       File containing the password. Mutually exclusive
                             with MEMGRAPH_PASSWORD. Missing/empty files fail
                             closed; prefer this in production.
MEMGRAPH_DATABASE            Logical database. Default: memgraph default.
                             With bolt:// the package issues USE DATABASE on
                             every session; with neo4j:// it is passed
                             natively. FAIL-CLOSED since 1.2.0: a non-default
                             name the server refuses (no Enterprise licence,
                             i.e. Memgraph Community) aborts boot and makes
                             /ready report the database as failed — it is
                             never silently replaced by the default database.
                             Unset it on a single-database (Community)
                             deployment.
TWIN_VECTOR_INDEX_CAPACITY   Capacity of each Memgraph vector index
                             (CREATE VECTOR INDEX ... "capacity"). Positive
                             integer, default 100000; a malformed value
                             refuses to boot. Applied at index CREATION only:
                             an existing index keeps its capacity (drop and
                             recreate to resize). Shown in
                             GET /twin/api/system/about (admin).
MEMGRAPH_ENCRYPTED           "true" to force TLS on plain bolt://. A WARNING
                             is logged when credentials would transit in
                             clear to a remote host.
MEMGRAPH_TRUST               Trust policy for TLS certificates.
                             TRUST_SYSTEM_CA (default), TRUST_CUSTOM_CA, or
                             TRUST_ALL (verification disabled; never production).
MEMGRAPH_CA_FILE             CA certificate path required by TRUST_CUSTOM_CA.
MEMGRAPH_POOL_SIZE           Connection pool size (write pool). Default: 50.
MEMGRAPH_READ_POOL_SIZE      Connection pool size (read pool). Default: 20.
MEMGRAPH_WRITE_CONCURRENCY   Max concurrent writes (semaphore). Default: 8.
                             Reads have no global throttle.
TWIN_GRAPH_MEMBERSHIP_FANOUT Maximum concurrent membership/override reads in
                             one folder-scoped native graph call. Positive
                             integer, default 2; malformed, zero, or negative
                             values also fall back to 2. Setting 1 serializes
                             these reads. One Graph render issues the entities
                             and relations calls together, against the same
                             MEMGRAPH_READ_POOL_SIZE shared by other routes;
                             raise this value only after sizing that combined
                             pressure. An unbounded 5-way fan-out measured +51%
                             p95 on concurrent chunk expansion.
MEMGRAPH_WRITE_SLOT_ACQUIRE_TIMEOUT
                             Seconds to wait for a write semaphore slot.
                             Default: 5.
MEMGRAPH_CONNECTION_ACQUIRE_TIMEOUT
                             Seconds to wait for a pooled connection. Default: 5.
MEMGRAPH_OPERATION_TIMEOUT   Maximum seconds for one pooled or graph-storage Bolt
                             operation, including driver/session acquisition,
                             large UNWIND batches, and session/driver closure.
                             Default: 60. Measure production ingestion batches
                             and raise this value when their legitimate work can
                             exceed 60 seconds.
MEMGRAPH_IDLE_DISCONNECT_SECONDS
                             Force write/read driver recreation after this many
                             seconds without pool activity. Default: 3600.
MEMGRAPH_MAX_CONNECTION_LIFETIME
                             Max age (seconds) of a pooled Bolt connection before
                             the driver recycles it without I/O. Lower it below the
                             network path's idle-kill window (Docker Swarm
                             overlay/IPVS resets idle TCP around 900s; e.g. 600) to
                             silence reset-by-peer log noise — the liveness probe
                             already keeps defunct sockets from reaching callers.
                             Default: 1800.

1B. KB PORTABILITY EXPORT / IMPORT (CLI + admin jobs; all optional)
--------------------------------------------------------------------------------
TWIN_PORTABILITY_DIR         Private parent directory for exported KB bundles,
                             browser uploads, persisted admin jobs, reports and
                             checkpoints.
                             Default: {WORKING_DIR}/portability (or
                             ./portability when WORKING_DIR is unset).
                             The CLI and server create directories 0700 and
                             files 0600. Browser uploads are capped at 100 MiB
                             compressed; use the CLI for larger archives.
TWIN_PORTABILITY_MAX_BYTES   Maximum decompressed bundle size accepted by
                             `portability inspect`, in bytes. Positive integer;
                             default 2147483648 (2 GiB). Checked member by
                             member before archive extraction.
TWIN_PORTABILITY_BATCH_SIZE  Keyset page size for store export/import. Positive
                             integer; default 1000.
TWIN_PORTABILITY_INCLUDE_ACTIVITY
                             "on"/"true"/"yes"/"1" exports the folder-scoped
                             activity feed. Default off; `--include-activity`
                             enables it for one command.
TWIN_PORTABILITY_INCLUDE_PROCEDURES
                             "on"/"true"/"yes"/"1" exports procedure review
                             records and their schematic PNG files. Default
                             off; `--include-procedures` enables it once. A
                             degraded procedure store refuses the export.
TWIN_PORTABILITY_ALLOW_UNVERIFIED
                             "on"/"true"/"yes"/"1" lets import dry-run accept
                             a bundle whose pre/post export consistency is
                             unverified. Default off. Never enable for a
                             production promotion; every use remains explicit
                             in the approved report.
TWIN_PURGE_LLM_CACHE_ON_FAILED
                             "0"/"false" disables the purge of LLM
                             entity-extraction cache rows tied to a document
                             that lands in FAILED status (LightRAG-native
                             behavior: cache rows survive the failure and a
                             re-ingestion replays them). Default: enabled —
                             a FAILED doc's extraction cache is deleted so
                             the re-ingestion re-calls the LLM.
TWIN_MAGE                    MAGE capability tier. "auto" (default) probes the
                             connected instance via CALL mg.procedures();
                             "off" forces the floor tier (base memgraph image,
                             storage + LLM curation only); "on" trusts the
                             operator that MAGE is present and skips the probe.
                             The floor tier is fully functional — MAGE only
                             unlocks additive graph-algorithm features
                             (Louvain, Katz), never the storage backends.
TWIN_EMBEDDING_TIMEOUT       Per-attempt timeout (seconds) for storage-side
                             ingestion embedding calls. Default: 30. Raise it
                             for a legitimately slow (not cold) endpoint.
TWIN_EMBEDDING_ATTEMPTS      Number of embedding attempts before failing a
                             document. Default: 3 (>= 1). Retries recover a
                             cold embedding endpoint; the last error is
                             re-raised on exhaustion (doc marked FAILED).
TWIN_CONVERT                 MarkItDown pre-conversion tier
                             (docs/adr/005-markitdown-ingestion-supply-chain.md). "auto" (default)
                             enables it iff the [convert] extra is installed;
                             "on" forces it (warns + native path if the import
                             fails); "off" disables — native extraction is
                             byte-identical to an unpatched install. Effective
                             on the lightrag_server entrypoints (twin_main.py,
                             -m lightrag_server, asgi.py) — the seam rides the
                             create_app wrapper.
TWIN_CONVERT_FORMATS         Comma list of extensions routed through
                             conversion. Default: pdf,docx,pptx,xlsx,xls,msg,
                             epub,html,htm,csv. ZIP is deliberately excluded
                             (no upstream zip-bomb guard); reintroducing it
                             here logs a SECURITY warning (audit 2026-08-06,
                             R-08c).
TWIN_CONVERT_MAX_BYTES       Size cap above which conversion is skipped
                             (native path). Default: 104857600 (100 MB).
TWIN_CONVERT_TIMEOUT         Per-conversion timeout in seconds (native path
                             on expiry). Default: 120.
TWIN_PRECONVERTED_PARSE      Kill-switch for the 1.5.x preconverted-markdown
                             parse seam (paragraph-citation phase B1). Unset
                             or any value but "off": the seam engages
                             automatically when the installed LightRAG
                             supports docs_format/parse_engine (never on the
                             1.4.x line). "off": converted markdown keeps the
                             historical raw enqueue, no block provenance.
TWIN_VISION                  Vision image-ingestion tier (PR 2). "auto"
                             (default) enables it iff openai is importable
                             AND TWIN_VISION_BASE_URL + TWIN_VISION_MODEL
                             are set; "on" forces (warns when unusable);
                             "off" disables — image uploads then follow the
                             native LightRAG behavior (rejected extension).
TWIN_VISION_BASE_URL         OpenAI-compatible endpoint serving a
                             vision-capable model (BNP: Gemma 4 31B-it via
                             LLMaaS/vLLM). Required for the tier. Passed
                             verbatim to the vision client — pin the host at
                             the deployer level; a compromised env turns it
                             into SSRF (audit 2026-08-06, R-08a: accepted
                             trust boundary, runbook-documented).
TWIN_VISION_API_KEY          API key for that endpoint. Default: dummy
                             ("twin-vision" — vLLM does not check it).
TWIN_VISION_MODEL            Model name on the endpoint. Required.
TWIN_VISION_FORMATS          Comma list of image extensions. Default:
                             png,jpg,jpeg.
TWIN_VISION_MAX_BYTES        Image size cap (refused above). Default:
                             20971520 (20 MB).
TWIN_VISION_TIMEOUT          Whole-pipeline timeout per image (OCR + LLM),
                             seconds. The same timeout is enforced on the
                             OpenAI transport and SDK retries are disabled.
                             Default: 60.
TWIN_VISION_MIN_OCR_CHARS    RapidOCR pre-filter: an image whose OCR text is
                             below this many chars is refused WITHOUT a
                             vision call (Knowledge-Bot economics). Default:
                             20. Set 0 to caption every image. RapidOCR not
                             installed → pre-filter bypassed (warn once).
TWIN_VISION_DROP_CLASSES     Vision classifications refused after the LLM
                             call. Default: invalid,logo,signature.
The two knobs above are the ONLY runtime-overridable vision settings:
Settings → Vision in the WebUI (PUT /twin/api/settings/vision, admin-gated)
persists per-workspace values in Memgraph that take precedence over these
env defaults, effective immediately across workers (re-read per image).
Endpoint/key/model/timeouts/caps stay env-only by design (secrets + SSRF
surface do not belong in a UI-mutable store).

TWIN_PDF_VISION              Generic visual enrichment for standard PDFs.
                             "auto" (default) enables it when pypdfium2 and
                             the Vision tier are available; "off" restores
                             the previous text-only PDF path. The procedure
                             profile always has priority. OCR is enrichment,
                             never a minimum-text rejection gate here.
TWIN_PDF_VISION_MAX_BYTES    PDF size cap for visual inspection. Existing
                             converted text still ingests above the cap.
                             Default: 104857600 (100 MB).
TWIN_PDF_VISION_MAX_PAGES    Maximum pages inspected per PDF. Default: 200.
TWIN_PDF_VISION_MAX_VISUALS  Maximum distinct visual candidates described
                             per PDF. Default: 40.
TWIN_PDF_VISION_MAX_RENDERS  Maximum regions rendered and fingerprinted per
                             PDF, including duplicates. This separate budget
                             lets duplicates found after the distinct cap
                             retain page provenance without unbounded work.
                             Default: 400.
TWIN_PDF_VISION_RENDER_SCALE PDFium render scale for images/scans/composite
                             pages (1.0 = 72 dpi). Default: 2.0; accepted
                             range: 0.5–4.0. Renders are capped at 16 MP.
TWIN_PDF_VISION_TIMEOUT      Whole-document enrichment timeout in seconds.
                             Default: 300.
TWIN_PDF_VISION_CONCURRENCY  Concurrent generic-PDF Vision transport calls
                             across the worker process. A timed-out coroutine
                             keeps its slot until the sync HTTP call stops.
                             Transport uses a dedicated bounded thread pool,
                             so queued calls cannot starve unrelated async
                             conversion, OCR or PDF-discovery work.
                             Default: 2; hard maximum: 8.

TWIN_PROCEDURE               Procedure-PDF ingestion profile
                             (docs/adr/007-procedure-pdf-profile.md). On Twin server
                             surfaces, activation is controlled per workspace
                             by the admin toggle in Settings > Vision and a
                             workspace with no saved choice starts OFF.
                             "on" seeds that unsaved default to ON when the
                             PDF + Vision prerequisites are available; "auto"
                             (default) and "off" seed it OFF. Once saved, the
                             runtime choice is authoritative. On direct
                             non-server surfaces only, the legacy behavior
                             remains: "auto" enables when pypdfium2 + pypdf
                             and Vision are ready, "on" requests enablement,
                             and "off" disables.
                             When active, a detected (or X-Twin-Doc-Type:
                             procedure forced) document is parked as an
                             approval bundle and NOT enqueued until a human
                             approves it. When inactive, new auto-detected
                             files use the standard path; an explicitly forced
                             procedure is parked failed, and paths already
                             claimed by a bundle remain claimed so a rescan
                             cannot bypass approval.
TWIN_PROCEDURE_STORE_FILE    Approval-bundle store (JSON file, atomic
                             writes, PNGs base64-inline). Default:
                             {WORKING_DIR}/twin_procedure_bundles.json.
                             A corrupt store is quarantined as
                             <name>.corrupt-* and the profile then FAILS
                             CLOSED for every file (the claim index is
                             lost) until an operator inspects and removes
                             the quarantine files.
TWIN_PROCEDURE_RENDER_SCALE  pypdfium2 page-render scale for schematic
                             pages (1.0 = 72 dpi). Default: 2.0. Accepted
                             range 0.5–8.0 (out-of-range falls back).
TWIN_PROCEDURE_MAX_SCHEMATICS  Cap on "Schematic:" pages processed per
                             document (excess logged and skipped).
                             Default: 8.
TWIN_VISION_EXTRA_BODY       Vendor-specific request extensions, as a JSON
                             object merged into the chat-completions call.
                             Empty by default: the product knows about no
                             particular gateway. Exists because one model id
                             can be served by several backends with different
                             behaviour, and only the deployment knows which it
                             trusts. CI uses it to pin an OpenRouter provider
                             (see .forgejo/workflows/ci.yml); BNP's vLLM sets
                             nothing.

TWIN_PROCEDURE_MAX_TOKENS    Completion cap for the two vision passes and
                             the comparator. Default 16384; values below 2048
                             are ignored. Sized for the WORST realistic
                             schematic, not the average: hitting the cap is
                             not a graceful degradation, a JSON object cut
                             mid-structure is unparseable and the whole
                             schematic is lost. Runaway protection belongs to
                             TWIN_VISION_TIMEOUT, not to this value.

TWIN_PROCEDURE_MAX_BYTES     Size cap above which the profile is skipped
                             (standard path). Default: 104857600 (100 MB).
Upload header X-Twin-Doc-Type: "procedure" forces the profile, "standard"
bypasses auto-detection; anything else is a 400. Absent = auto-detect on
the first two pages' text (ITG reference + template markers).

3. AUTHENTICATION (three modes, in order of precedence)
--------------------------------------------------------------------------------
When NONE of the variables below is set, the server boots in open access
(LightRAG-parity): anonymous allowed, a loud "auth DISABLED" warning is
logged and the WebUI shows an open-access notice instead of Sign out.

Fail-closed production switch:
TWIN_ENV=production           Requires a configured auth backend at startup.
TWIN_REQUIRE_AUTH=true        Same requirement without changing the env name.
                              Production mode accepts LIGHTRAG_API_KEY,
                              LIGHTRAG_JWT_SECRET/TOKEN_SECRET, or
                              TWIN_IDP_JWKS_URL. It rejects local HS JWT
                              secrets shorter than 32 bytes and rejects the
                              default "changeme" password in
                              LIGHTRAG_JWT_PASSWORD or AUTH_ACCOUNTS.

Mode A — static API key:
LIGHTRAG_API_KEY             Static infrastructure root key. Twin routes accept it
                             as a bearer; LightRAG-native routes use X-API-Key.
                             When the IdP is dormant, this is the only credential
                             authorized for admin routes and non-default folder
                             selection. Local JWT and twk_ credentials remain
                             non-admin and are confined to the default folder.

Mode B — local JWT login (POST /login → HttpOnly cookie):
LIGHTRAG_JWT_SECRET          Signing secret. Enables /login.
LIGHTRAG_JWT_PASSWORD        Login password. "changeme" logs a SECURITY
                             warning outside production mode.
LIGHTRAG_JWT_USERNAME        Login username. Default: admin
LIGHTRAG_JWT_ALGORITHM       Default: HS256
LIGHTRAG_JWT_EXPIRATION_HOURS  Token TTL.
TOKEN_SECRET                 Legacy alias for the JWT secret (LightRAG native).
TOKEN_EXPIRE_HOURS           Legacy alias for the TTL.
AUTH_ACCOUNTS                LightRAG-native "user:pass,user2:pass2" list.

Login brute-force throttle (audit 2026-08-06, R-04):
TWIN_LOGIN_RATE_LIMIT_PER_MINUTE  Per-source-IP sliding-window limit on
                             POST /login attempts; excess gets 429 +
                             Retry-After. Default: 5. 0 disables (NOT
                             recommended outside tests). The limiter keys on
                             the socket peer and deliberately does not trust
                             X-Forwarded-For.
TWIN_LOGIN_BACKOFF_MAX_SECONDS  Cap on the per-account exponential backoff
                             applied to consecutive failed logins (1s from
                             the 3rd failure, doubling, capped here).
                             Default: 30. 0 disables the backoff. A
                             sev=critical audit event + SECURITY log fire
                             every 10 consecutive failures per account.

Mode C — corporate IdP (JWKS). Setting TWIN_IDP_JWKS_URL activates the strict
RBAC posture; leaving it unset keeps the middleware dormant:
TWIN_IDP_JWKS_URL            JWKS endpoint URL.                [activation switch]
                             Must be https:// — a plain-http endpoint logs a
                             SECURITY warning at boot (audit 2026-08-06, R-08e).
TWIN_IDP_ISSUER              Expected issuer claim.
TWIN_IDP_AUDIENCE            Expected audience claim.
TWIN_IDP_ALGORITHMS          Allowed algorithms. Default: RS256
TWIN_IDP_COOKIE_NAME         Cookie carrying the JWT (fallback: Authorization).
TWIN_IDP_JWKS_CACHE_TTL      JWKS cache TTL (seconds).
TWIN_IDP_NAME                Display name of the IdP.
TWIN_IDP_REALM               Display realm.
TWIN_IDP_LOGOUT_URL          Front-channel logout URL for the WebUI.
TWIN_IDP_CLAIM_SUBJECT       Claim name mapping → subject.
TWIN_IDP_CLAIM_EMAIL         Claim name mapping → email.
TWIN_IDP_CLAIM_NAME          Claim name mapping → display name.
TWIN_IDP_CLAIM_GROUPS        Claim name mapping → groups list.
TWIN_IDP_CLAIM_SCOPES        Claim name mapping → scopes.
TWIN_IDP_CLAIM_FOLDERS       Claim name mapping → authorized Twin folders.
TWIN_IDP_ADMIN_GROUPS        Groups granted the admin:folders scope.
TWIN_IDP_GROUP_TO_PALIER_JSON  JSON map group → palier level.

Open-access identity (only when no auth backend is configured):
TWIN_DEBUG_USER_EMAIL        Default: operator@example.com
TWIN_DEBUG_USER_NAME         Default: operator@example.com

5. DOCUMENT CLASSIFICATION (Microsoft Information Protection labels, opt-in)
--------------------------------------------------------------------------------
TWIN_MIP_LABEL_MAP           Path to a JSON map GUID → class id (e.g. C1..C4).
TWIN_MIP_MAX_CLASSIFICATION  Ceiling; documents above it are rejected at
                             ingestion with an audit event. Default: C2.
TWIN_MIP_UNLABELED_POLICY    "allow" (default — decision 2026-07-10) ingests
                             documents WITHOUT a readable MIP label (images,
                             csv/html, unlabeled OOXML/PDF, olefile/pikepdf
                             missing), tracing class None in
                             DocStatus.metadata.classification. "reject"
                             restores the tier-1 fail-closed posture (every
                             unlabeled document refused).
When the MIP hook is active: a READABLE label above the ceiling and an
untrusted UNKNOWN label (unmapped GUID, extraction crash) always reject;
unlabeled documents follow TWIN_MIP_UNLABELED_POLICY; source-less ingestion
still fails closed regardless of the policy (provenance, not labels).
Operator C1/C2 input may raise, but never replace, source provenance.
Raw-text /insert is disabled; ingest classified binaries via /documents/upload.

6. WEBUI OVERLAY / RUNTIME CONFIG
--------------------------------------------------------------------------------
TWIN_API_BASE_URL            Base path injected into the WebUI. Default: /twin/api
TWIN_LIGHTRAG_BASE_URL       Optional separate origin for native LightRAG routes.
TWIN_CATALOG_URL             Central KB catalogue http(s) origin. Must be set
                             together with TWIN_CATALOG_INSTANCE_CREDENTIAL.
                             When both are absent, linked-source routes are not
                             mounted and the WebUI keeps its legacy Coming-soon
                             state. In production, use the internal HTTPS origin.
TWIN_CATALOG_INSTANCE_CREDENTIAL
                             Secret credential issued to this KB with the
                             links:write scope. It stays server-side: the Twin
                             proxy forwards it as Bearer while the browser sends
                             only its normal user auth and X-Twin-Folder. The
                             credential's KB/AUID binding is authoritative.
When catalogue integration is enabled, `/twin/api/catalog-profile` is also
mounted. It accepts only the infrastructure root or a dedicated `tcp_` key
created by `POST /twin/api/settings/api-keys` with scope `profile:read` and an
explicit folder allow-list; that key cannot authenticate on generic Twin
routes. The central catalogue stores it as the per-KB scan credential.
LIGHTRAG_ENABLE_WEBUI_ROUTES true/false — mount the /twin/api overlay.
LIGHTRAG_WEBUI_TAG_BACKEND            "memgraph" (persistent) or "memory".
LIGHTRAG_WEBUI_ACTIVITY_BACKEND       idem.
LIGHTRAG_WEBUI_NOTIFICATIONS_BACKEND  idem.

7. TRACING (optional)
--------------------------------------------------------------------------------
LIGHTRAG_ENABLE_LANGSMITH_TRACING  true/false
LANGSMITH_API_KEY            LangSmith key.
LANGSMITH_PROJECT            LangSmith project name.

Distributed HTTP context needs no additional feature flag. Both the standalone
factory and the production LightRAG host accept W3C `traceparent`,
`langsmith-trace` / `x-langsmith-trace`, and the legacy `x-trace-id` fallback.
Priority for the canonical HTTP trace is: valid W3C > valid LangSmith trace UUID
> bounded custom id > newly generated context. A malformed/absent W3C parent is
never reflected: the runtime creates a non-zero trace id and server span id.
Every normal response returns `x-request-id` and the canonical `traceparent`.
Twin-owned downstream HTTP calls forward that context. When LangSmith tracing
is enabled, LightRAG LLM/embedding/rerank spans and L3 provider-call spans also
inherit the native LangSmith parent and carry the W3C trace/span ids as
metadata.

TWIN_LOG_FORMAT              "text" (default) keeps the development/operator

                             handlers. Any other value refuses app creation.

                             fail-closed production auth switch in section 3.
PROMETHEUS_MULTIPROC_DIR     Optional directory for official prometheus-client
                             multi-worker aggregation. It MUST be configured
                             before Python imports the server, writable by all
                             workers, and emptied by the process manager before
                             each start. Leave unset for the default mono-process
                             runtime.

Authenticated operator endpoints under LIGHTRAG_WEBUI_API_PREFIX:
  GET /ops/metrics             stable JSON compatibility counters
  GET /ops/metrics/prometheus  Prometheus text exposition

Prometheus labels use fixed route/method/status vocabularies; raw paths, folder
ids, users and document ids are never labels. Request/auth/quota/storage counts
and route-group latency are live. Activity events are validated against the
shipped AuditEvent v1 contract, so audit_invalid_total is live now. Audit drops
and queue depth become live only when the durable exporter (#122) installs its
sink/queue. Technical logs never replace that business/regulatory contract.
